# Cricket coverage and playback matching

Cricket uses ESPN's Cricket header scoreboard directly. International and domestic events keep their source event/team IDs, complete innings strings, format, and session/status wording. Tests remain relevant beyond their first day, through their supplied end time. An ongoing Test can be at stumps or delayed; an ongoing fixture does not establish that a provider is broadcasting it now.

Daily requests are independent and coalesced. A failed date no longer discards the successful dates. Partial responses update known fixtures by ID and retain previously cached fixtures from the missing dates. They report an incomplete refresh and remain eligible for retry. A complete empty response can clear fixtures; an outage cannot.

Channel discovery scans the live catalog for team evidence even when the provider does not label a channel Cricket. Playback matching then requires both sides in a current programme or an explicit event channel with no conflicting guide. Broadcasters alone, other opponents/squads, expired listings, highlights and replays do not prove coverage. Later-day Test listings use the current programme slot rather than the original match start.

India, India A, India Women and India U19 remain different sides. Aliases cover explicit country codes and compact qualified codes such as INDA/NZA and ASW/MSW. Women's and youth competition labels can supply the qualifier when the programme omits it from individual team names. A match number or score of 19 is not a global U19 marker. Older cached empty Cricket results are retired after this policy update; existing verified proof keeps its original expiry.

On iPhone, the match picker and TV Guide search channel names and the programme covering the requested time. Search accepts either team order and preserves an A/W token as a word. It ignores past/future programmes at the current time. Guide retains its hidden-category policy; the game picker exposes the live catalog. Manual search is discovery, not verification that a stream carries the match.

Manual match selection uses the same provider URL construction as Guide playback. No Cricket-specific codec, buffer or decoder changes were justified by the available evidence. The reported Meteor channel failure cannot be reproduced without the actual channel and player error; a successful build or matching fixture test does not demonstrate that every provider stream loads.

Regression coverage includes captured ESPN fixtures, later-day Test restore/playback, the raw-catalog preparation pipeline, squad/code/competition aliases, match-number handling, partial-date refresh and saved-feed retention, current-programme search, unrelated favorites, and the existing 30,000-channel search/rendering checks. Apple SDK tests and app builds run in GitHub Actions.

Startup discovery now requires aliases for both sides in the same channel name or programme covering that game's matching time. A single common word such as `new` from New Zealand or `as` from AS-W previously admitted unrelated entertainment channels into the full prepared-guide cache. A 30,000-channel regression retains the two real feeds and excludes unrelated current programmes and real matches listed only for later. The shared professional index also stores each stream ID once across league buckets. A native provider-load regression exercises the complete preparation pipeline with the same large catalogue while the UI actor continues running.

The iPhone workflow builds the optimized simulator app and launches it independently of XCTest with a saved provider and Cricket schedule. Startup validation has its own parallel job and builds only the selected simulator's active architecture, so the full test suite and another optimized build do not consume the same job budget. A cold optimized build has a 45-minute step budget within a 90-minute job that also allows targeted optimized player lifecycle tests. Build outputs and resolved packages are cached by platform, architecture, Xcode version, project configuration and app source; successful compilation is saved before launch validation so a runtime failure does not discard it. Cache failures are optional; the build and launch checks always run. It inspects the exact launched PID, executable path and process state directly: an absent entry in `launchctl`'s service table does not establish that a simulator app exited. Both the initial launch and relaunch must retain a live process and show the Sports screen in the captured image. Screenshots, direct stdout/stderr, logs and available crash reports are retained on failures too. A screenshot failure cannot mask a process exit, and failed launches get a bounded debugger replay for native abort backtraces without changing the failure result. IPA publication requires tests, startup validation and packaging to pass. Simulator commands have bounded timeouts. Manual build requests queue without canceling an earlier requested build.

The simulator frontend is resolved within the selected Xcode installation. Xcode 27's Device Hub lives in `Contents/Applications/DeviceHub.app` and opens the created device through its `devices://device/open?id=...` URL; older Xcode uses `Contents/Developer/Applications/Simulator.app` with its original device argument. Compatibility checks cover a Device Hub-only installation, paths containing spaces, the legacy layout and rejection of a frontend from another Xcode. The native launch, screenshot and publication checks remain mandatory. See [Apple's Device Hub documentation](https://developer.apple.com/documentation/xcode/device-hub) and the [current Expo CLI launcher](https://github.com/expo/expo/blob/main/packages/@expo/cli/src/start/platforms/ios/ensureSimulatorAppRunning.ts).

The standalone Release check captured a native `Pure virtual function called!` abort immediately after VLC initialization; the process had exited before the screenshot attempt. Sports and Guide were creating VLC and AVPlayer in idle controllers before a stream was selected. Both players are now allocated on demand and retained for reuse. Idle surfaces, diagnostics, mute changes, background transitions and teardown operate only on engines already allocated. Native regressions cover idle lifecycle, individual engine allocation and reuse, and existing drawable/session ownership. These also run with Release optimization after the standalone launch check; testability is enabled only for that app test build, not for shipping builds or third-party decoder packages. The captured abort does not identify the exact failing native frame or establish that the user's physical-device crash has been resolved. The full Debug native suite and physical Release packaging passed with the player lifecycle changes; standalone optimized startup and device behavior still need validation.
